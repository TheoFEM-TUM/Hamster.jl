Hyperparameter Optimization

Hamster.run_calculation — Method
run_calculation(::Val{:hyper_optimization}, comm, conf; rank=0, nranks=1, verbosity=get_verbosity(conf))

Perform a hyperparameter optimization by evaluating the model over many parameter configurations and identifying the one that yields the lowest loss.

This routine drives the full hyperparameter-search workflow, including parameter sampling, model evaluation, bookkeeping, and reporting of results. It supports random search, grid search, and Tree-Parzen Estimator (TPE; Bayesian optimization).

Workflow

  1. Check the settings and determine the number of candidates. The hyperparameter labels are resolved to input tags (see Hamster.hyperopt_tag) and the lists of the HyperOpt block are checked. Random search and TPE evaluate niter candidates, grid search evaluates all points of the grid (niter is not used).

  2. Sample the training and validation configurations. The configurations are sampled once and used for all candidates, so that all candidates are compared on the same data. Only if a hyperparameter changes the sampling (a tag of the Supercell block, val_ratio, validate, train_mode or val_mode), they are sampled again for every candidate.

  3. Construct the search space.

    • For TPE, a probabilistic search space is built using quantized uniform distributions.
    • For random and grid search, discrete candidate values are generated directly from lowerbounds, upperbounds and stepsizes.

  4. Iterative evaluation. For each candidate:

    • A set of hyperparameters is sampled from the search space.
    • A fit is run with these parameters using hyper_optimize, which returns the score of the candidate: the lowest validation loss of the fit if the fit is validated, else the lowest training loss.
    • For TPE, the sampled point and its score update the optimization history to refine future proposals.
    • The results so far are written to hamster_out.h5, so they are kept if the run stops early.

  5. Select the best configuration. After all candidates, the routine identifies the parameter set with the lowest score and prints a summary (if verbosity > 0).

Required Inputs

  • Training data set (see Optimizer).
  • Validation data set (optional; see Optimizer).

Settings (from the HyperOpt block)

  • params – Names of the hyperparameters to optimize: tag for a tag of the Options block (or a tag that exists in only one other block), Block_tag for a tag of another block (e.g. ML_rcut) and Element_tag for a tag of an atom block (e.g. Ga_alpha).
  • lowerbounds, upperbounds – Numerical bounds for each parameter.
  • stepsizes – Step size used for random/grid sampling and quantization.
  • niter – Number of candidates for random search and TPE.
  • mode – Sampling strategy: random, grid, or tpe.

Output Files

  • hamster.out – Standard Hamster output.
  • hamster_out.h5 – HDF5 file, written after every candidate, containing:
    • L_train: the score of each candidate (the lowest validation loss if the fits are validated, else the lowest training loss),
    • L_val: the lowest validation loss of each candidate (zero without validation),
    • L_fit: the lowest training loss of each candidate,
    • timings: the time of each fit,
    • one dataset per hyperparameter with its value for each candidate, and params, the list of hyperparameters,
    • train_config_inds and val_config_inds: the configurations of the fits (if they are the same for all candidates),
    • the attribute evaluated: the number of evaluated candidates (the entries of later candidates are zero).
